# Piano Practice

A native piano trainer for iPhone, iPad and Mac, written in Swift and SwiftUI. It teaches an adult beginner to read
sheet music and play their own pieces, with a learning path built on published research on memory and practice
(see [docs/DESIGN.md](docs/DESIGN.md)).

The interface is in Italian (Do Re Mi note names); code, comments and docs are in English.

## Features

- **Practice your pieces** – opens MusicXML (`.musicxml`, compressed `.mxl`) and standard MIDI files; falling notes,
  a full staff that follows the playing, and the practice waits for the right keys (chords must be held together).
  Choose a bar range with a two-thumb slider, one hand or both, tempo, loop, "practise the weak spots".
- **MIDI keyboard** – any CoreMIDI source (USB on the Mac, the camera adapter on the iPad), reconnected when devices
  come and go; pads and the pitch wheel drive the trainer (restart, step, listen, hands).
- **Grand piano sound** – Salamander Grand Piano samples, one every minor third and pitch-shifted, played by a
  custom `AVAudioSourceNode` render callback: a key starts within one IO buffer (~5 ms) and the "listen" mode
  schedules a whole lesson on the audio clock.
- **Learn to read** – a staff drawn in SwiftUI (clefs, key signatures, ledger lines, accidentals); quizzes for keys,
  treble, bass, key signatures and chords, answered with big name buttons or on the MIDI keyboard.
- **Spaced repetition** – Leitner-style review dates per note (1 → 32 days), "known" = right *and* fast, live review
  of the notes missed in this round, AFK detection so the timing stays honest.
- **Guided path** – 5 stages (keyboard and fingers, treble, bass, chords, sharps/flats and keys), a ~15-minute daily
  session, and sight-reading melodies generated by the app.
- **Fingering** – suggested five-finger positions where the score has none, starting hand position for each
  lesson, a drawn hand with the finger to use.
- **Statistics** – time per note, first-try %, slowest notes, per-bar difficulty, practice minutes, days in a row.
  Optional sync between devices through a small self-hosted HTTP service (off by default).

## Architecture

```
Piano/                      the app target (SwiftUI App, one window per platform)
Piano.xcodeproj             one project: iOS 17+ and macOS 14+
Packages/PianoKit/          Swift package
  Sources/PianoKit/           model, no UI: Piece (MusicXML/MIDI readers), Trainer, NoteQuiz + QuizStore,
                              Stats, Path, SightReading, Fingering, Chords, MIDIInput (CoreMIDI), Sampler (audio)
  Sources/PianoUI/            SwiftUI screens shared by iPhone, iPad and Mac
  Sources/DesignKit/          design tokens, glass surfaces, dashboard tiles
  Tests/PianoKitTests/        XCTest: reader snapshot, trainer, quiz rules, path, sync merge
pieces/                     bundled pieces (public domain)
sources/ + tools/           compact text transcriptions → MusicXML (compact2musicxml.py)
vendor/salamander/          piano samples (CC BY 3.0)
docs/DESIGN.md              the learning design and its research
```

Notes:
- `PianoKit` has no UI dependency, so the learning logic (review scheduling, "known" rules, hint selection, path
  progression) is unit-tested on its own: `swift test` runs in a few seconds without a simulator.
- Observation (`@Observable`) everywhere; state is per-device JSON files, merged when synced (the latest answer for
  a note wins, counts add up without double counting).
- iPhone opens on *Impara* (learn, touch only); iPad and Mac open on practice, where the MIDI keyboard is plugged in.

## Build

Requirements: Xcode 26+ (the Liquid Glass APIs are behind `#available`, so the app still runs on iOS 17 / macOS 14).

```sh
cd Packages/PianoKit && swift test        # unit tests
./build.sh mac                            # → build.noindex/Piano.app (ad-hoc signed)
./build.sh sim                            # booted iOS simulator
DEVELOPMENT_TEAM=<your team id> ./build.sh device   # a paired iPhone/iPad (DEVICE_NAME=iPhone)
```

Or open `Piano.xcodeproj`, set your team under *Signing & Capabilities*, and run.

Your own pieces: *Apri…* (⌘O) on the Mac, or drop `.musicxml`/`.mxl`/`.mid` files in the app's pieces folder.

### Optional sync

Set `PianoSyncServer` (`host:port`) in `Piano-Info.plist` or in the app's UserDefaults. The app sends
`PUT /piano/state/<device-id>` with its own answers and reads `GET /piano/state` (`{"devices": {id: doc}}`).
There is no authentication in the protocol: run the server only on a private network or VPN.
